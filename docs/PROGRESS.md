## Отклонения от спецификации

### Этап 1
- **Проверка на устройстве не выполнена**: в среде исполнителя нет macOS/Xcode. Критерий «запускается
  на iPhone» и `flutter build ios --no-codesign` (§13.3.1) — за заказчиком.
- **DAO слиты с репозиториями** (§10 перечисляет `daos/*`): запросы пишут репозитории
  `features/*/data/` поверх `AppDatabase`; менеджеры drift выключены (`build.yaml`). Слоёв меньше,
  граница I13 та же — presentation не видит drift.
- **Без riverpod_generator**: провайдеры объявлены вручную; `riverpod_annotation` и генератор убраны
  из зависимостей — меньше codegen, те же провайдеры.
- **`parseAmount`**: ровно три цифры после последнего разделителя при `minorUnits < 3` — разделитель
  групп («1,234» = 1234), иначе лишние знаки — отказ. В §4.1 этого не было; без правила «1,234»
  отвергалось бы.
- **Перенос из Flashcards**: `docs/learn/` не перенесён (учебник по коду Flashcards), из `docs/rules/`
  взят только `10-agent-workflow.md` (на него ссылаются скиллы). Скилл `shots` переписан под кадры из
  `flutter test` вместо симулятора (симулятора в среде нет); `tool/shots.sh` — на этапе 5.
- **§12.2 (НБКР) не проверен**: сеть контейнера не пускает на nbkr.kg (403 на прокси). Разбор
  пишется по известному формату `CurrencyRates/Currency[@ISOCode]/Nominal/Value` с запятой в числе и
  проверяется на фикстуре; подтвердить на устройстве.

### Этап 3
- **Уведомления перепланирует слежение за базой** (`ReminderSync`: `tableUpdates` правил, наступлений,
  операций, настроек, курсов; пачка изменений — один `replan` через 0,8 с) вместо вызова после каждого
  `OccurrencePlanner.replan` и каждой правки (§6). Это надмножество требования: новый экран не может
  «забыть» перепланировать. Плюс явный `replan` при старте и при возвращении из фона.
- **«Remind tomorrow» живёт до следующего полного `replan`**: `cancelAll` снимает и его. Сохранять
  отложенные напоминания в базе — отдельная таблица, в v1 не заведена.
- **Фоновое действие «Paid»** (§6.6, §12.5) написано по спецификации: `AppDelegate` регистрирует плагины
  для фонового движка (`setPluginRegistrantCallback`) и назначает делегата центра уведомлений (страж в
  `invariants_test.dart`, перенесён из Jattap и дополнен). На устройстве не проверено.
- **Подписи действий уведомления** («Paid», «Remind tomorrow») регистрируются при запуске на языке
  приложения; смена языка применится к ним со следующего запуска.
- **Разрешение на уведомления** спрашивается после сохранения правила, кредита или кредитной линии с
  напоминаниями (§6: «первого напоминания у правила»); переключатель в настройках — этап 4.
- **Правка счёта-пассива** (`ObligationRepository.syncRule`): имя правила — как у счёта; новый день оплаты
  кредитной линии — новое расписание. График кредита при правке счёта не трогается (последний платёж
  добирает итог, §3.4) — для него есть «Recalculate».
- **«Extra payment»** — перевод на счёт кредита (экран Add); график после него пересчитывается кнопкой
  «Recalculate» (keep payment / keep term), не автоматически.
- **Кредитная линия на экране счёта**: строка «Next <дата>» вместо «Due day», когда наступление есть.
- **Вёрстка по кадрам** (40 новых кадров × 4): сегмент не переносит подписи — сжимается целиком или
  делится поровну (`expand`); `ValueRow` уводит значение под подпись, если вместе не влезают («Следующее
  списание» на 320 pt); кнопка «Pay N» в строке занимает не больше ~38 % ширины, иначе — «✓ 2 584,31»
  (иначе имя обрезалось до «Si…»); под группами «Today»/«Tomorrow» подпись «Tomorrow» не повторяется;
  круглые действия выровнены по верху; «Pay» на экране наступления — целым, без переполнения.
- **Найдено тестами**: «Undo payment» на экране операции падал вёрсткой (тема задаёт `TextButton`
  бесконечную минимальную ширину) — `routes_test` не открывал связанную операцию; добавлен маршрут
  `transaction-paid`. Страж «пустой список вместо загрузки» поймал два места в новом коде — исправлены.
- **`routes_test.dart`**: 30 маршрутов × пустая/демо база × en/ru × 320/393. Демо-данные дополнены
  кредитом из скриншота Simbank, кредитной линией, подпиской в USD с автосписанием, коммуналкой без
  суммы и просроченным интернетом.
- Новые тесты проверены мутацией: `safe_to_spend` (3 мутации), `reminder_sync`, `notification_target`,
  `syncRule` (2) — красные на всех; виджет-тесты `payments_flow_test` краснеют на заглушках этапа 2.
- `flutter build ios --no-codesign` и критерий на устройстве не проверены (нет macOS).

### Этап 4
- **Фикстура НБКР написана по известному формату**, не сохранена с сайта: сеть контейнера не пускает на
  nbkr.kg (см. этап 1, §12.2). Разбор терпит запятую, номинал (100 сумов) и битые строки; формат
  подтвердить на устройстве — при расхождении правится только `parseNbkrDaily`.
- **«Remove budget»** — строка с суммой 0 с выбранного месяца, а не удаление: прошлые месяцы сохраняют
  свой бюджет (§9.4 «максимальный `from_month ≤ M`»). Сумма 0 = «бюджета нет».
- **Долг за 12 месяцев** считается назад от текущих балансов (баланс на начало дня = сейчас − операции
  с этой даты). Начальный долг счёта без даты: кредит учитывается с месяца перед первым платежом,
  кредитная линия — весь период. Курсы — текущие.
- **Переключатель «Reminders»** в настройках — это разрешение iOS: включение спрашивает его; выключить
  можно только в настройках iOS (тост об этом). Отдельного ключа «напоминания выключены» в §3.3 нет.
- **Версия в «About»** — константа `lib/app/version.dart` (без package_info); совпадение с `pubspec.yaml`
  сторожит тест.
- **Разбор курса** (`parseRateMicro`) — один на НБКР и ручной ввод, в `core/money.dart`, без `double`.
- **Вёрстка по кадрам**: в «Budgets» суммы «потрачено из бюджета» не обрезаются — «осталось» уходит на
  следующую строку; у категорий без бюджета вместо пилюли «Задать бюджет» — значок «+» (пилюля съедала

- Тесты проверены мутацией: `spent_test` (5 мутаций; одна выжила — нет операции ровно в день точки
  ряда долга — тест дополнен), `budget_test` (3); `stage4_flow_test` краснеет на заглушках.
- `flutter build ios --no-codesign` и критерий на устройстве не проверены (нет macOS).

## Известные ограничения
- Данные локальные, без шифрования; Face ID — замок экрана (spec.md I18).
- Подключения к банкам и разбора СМС нет и не будет (spec.md §0).
- «Remind tomorrow» живёт до следующего полного перепланирования уведомлений (этап 3).
- Подписи действий уведомлений меняют язык со следующего запуска (этап 3).
- Курсы для подсказок и итогов — текущие; `base_amount` операции — снимок на день записи (I8).

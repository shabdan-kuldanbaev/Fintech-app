# Самопроверка по I1–I20

Источник истины — таблица в `docs/spec.md` §1.

1. Возьми дифф: `git diff HEAD -- lib/` (или указанный диапазон/файлы).
2. Прогони стражей: `flutter test test/architecture/invariants_test.dart`.
   Они покрывают I1, I2, I3, I4, I5, I7, I11, I12, I13, I14, I16, I17, I18, I19 и
   чистоту domain/. Красно — чинить код, не стража.
3. Пройди по **всем** I1–I20 и на каждый ответь одной строкой: где в этом диффе
   он мог быть нарушен — и проверь это место чтением кода. Особое внимание тем,
   что держатся только на внимательности: **I8** (валюта транзакции = валюта счёта,
   `base_amount` при записи), **I9** (оплата и отмена оплаты — одна транзакция БД),
   **I10** (paid/skipped не трогаются перепланированием), **I15** (что считается тратой),
   **I20** (копия — всё, включая `deleted_at`).
4. Частые места нарушений:
   - `DateTime` из drift без `.toUtc()`; запись с `isUtc == false`;
   - календарная дата, посчитанная через `DateTime` мимо `LocalDate`;
   - сумма в `double`, `toStringAsFixed`, деление без `mulDivRound`;
   - баланс, записанный в колонку, вместо вычисления;
   - транзакция в валюте, отличной от валюты счёта;
   - оплата наступления двумя отдельными записями;
   - перевод на `credit_line` посчитан тратой, adjustment — в статистике;
   - `Text('…')` с буквами мимо `AppLocalizations`; новый ключ только в одном ARB;
   - `hashCode` в id уведомлений, `matchDateTimeComponents`;
   - цвета и шрифты мимо `app/theme.dart`; любая встроенная системная вью.
5. Нашёл нарушение — закрой **класс** по всему `lib/` (приложи команду поиска), и
   если класс выражается текстом — заведи стража в `invariants_test.dart`
   отдельной правкой с мутационной проверкой.
6. Отчёт: таблица I1–I20 → «не затронут» / «проверено: файл:строка» / «нарушение: …».

# Волна

Полное обоснование — `docs/rules/10-agent-workflow.md`. Здесь только порядок.

## Перед волной
1. Дерево чистое, состояние закоммичено (`git status --short` пуст) — есть куда откатиться.
2. Поиск — читающими агентами `auditor`, сколько нужно, параллельно. Их выводы —
   заявления: каждую находку перед починкой подтвердить чтением кода.
3. Раздели работу на **не больше 3–4** пишущих агентов. Выпиши зоны файлов:
   у каждого свой набор, пересечений нет.
4. Механизмы проверки (`tool/*.sh`, `test/architecture/`, помощники тестов,
   обработчики ошибок) в одной волне с проверяемым кодом не правятся — отдельная
   волна, потом мутация: сломай нарочно, убедись, что поймано.

## Запуск
5. Пишущие — агентом `wave-writer`, все в одном сообщении. В задании каждому:
   что чинить и почему (с доказательством: файл:строка), его зона файлов, чужие зоны.

## После волны — сам, не по отчётам
6. `tool/verify.sh` → строка `verify: ЗЕЛЕНО`. Красно и не чинится за один
   заход — волна откатывается целиком, а не латается. Откат уничтожает
   незакоммиченную работу: сначала покажи заказчику `git status --short` и
   получи явное согласие, потом `git checkout -- <зоны>` и удаление новых файлов зон.
7. Прочитай диффы глазами (`git diff`). Правки вне объявленных зон — разобрать.
8. Интерфейс затронут — скилл `shots`. Код в `lib/` — скилл `invariants`.
9. Один коммит на волну: что сделано, чем проверено, вывод команды. Запись в
   `docs/PROGRESS.md`; если меняется раздел «Сейчас» — поправить и его.
